\section{Introduction}
A coding agent inspecting a chart has a choice about what to send a second model. It can forward its inspection record, write a summary, or quote the task and identify the exact file it inspected. The chart itself can travel with all three requests. The second model supplies advice; the first decides what to save. A useful comparison must therefore track both the information at the handoff and the quality of the file that eventually reaches the user.

A structured packet can preserve a requirement that an informal summary omits. It can also spend more characters identifying a file than it saves by omitting an inspection log. To separate these effects, we hold the decision point, media, final executor, advisor route, and time budget fixed within each task. We compare the complete shareable checkpoint (Full), a free-text summary produced by the executor (Summary), and a packet built by the Spot Advisor 2.4 caller (Scoped). Here a checkpoint is a bounded task record assembled after a local inspection. It does not contain an entire developer session.

Our primary question is how much verified delivery quality could be lost by using the structured packet. A separate question is whether the entire workflow costs less per verified delivery. The summary condition provides a descriptive comparison under the same maximum text length. These questions are conditional on asking for advice. Every arm can consult once, so this experiment cannot estimate the value of initiating a consultation.

\section{Related work}
LLMLingua uses a budget controller and token-level selection to shorten prompts for inference \cite{llmlingua}. Kummer et al.\ measure the cost of compression itself and show that end-to-end latency depends on the hardware and length regime \cite{kummer}. Our unit of intervention is a handoff between two model roles. A summary adds an executor request, whereas a structured packet incurs local preparation and carries explicit provenance. Comparing advisor tokens alone would omit one of those costs.

Liu et al.\ vary the position of relevant information in long contexts and find that access to the same evidence does not guarantee the same answer \cite{middle}. Here the contexts are short, and the format can change which inspection details the advisor sees. FrugalGPT studies how a cascade can route queries among models with different prices and capabilities \cite{frugal}. We keep the same models within a task and vary the record sent between them. This isolates a question that a model-routing comparison would otherwise combine with the effects of model choice.

\section{Methods}
\paragraph{Sampling.}
We used seeded, modality-specific shuffles of the sanitized MBPP test split \cite{mbpp}, ChartQA test split \cite{chartqa}, and US English FLEURS test split \cite{fleurs}. Eligible programming tasks had a recognizable Python function signature, at least three supplied assertions and no test imports. A task exposed the signature and first assertion. Chart items required a labeled PNG of at most 300,000 bytes. Speech items were three to thirteen seconds long with at least five reference words. The sampler deduplicated task keys and normalized prompts or transcripts, retaining at most one question for any chart image and one recording for any sentence ID. We converted audio to 16-bit PCM WAV. Gold answers, reference transcripts and held-out assertions stayed outside model prompts.

\paragraph{Assignment and calibration.}
Each sampled source item defines a matched triple. The first \PilotN{} items across strata were reserved for calibration. During calibration, the parser rejected outputs containing a provider completion marker. The candidate was amended before confirmation and the same calibration tasks were run again with fresh responses. Both pilot cohorts remain archived and contribute no outcomes to the primary comparison. The amended pilot had \PilotDiscordant{} discordant Full--Scoped pairs. We used the upper one-sided 80\% exact binomial bound on discordance in a normal-approximation sample-size calculation with 80\% target power under equal success rates. This gave \DesignTarget{} tasks before the registered cap of \StudyN{}. The cap limited the precision available to distinguish small effects. For confirmation, each modality contributed equally. All six arm orders occurred equally often within each modality. Dispatches could overlap in wall time. The locally versioned protocol and analysis were published with the release after collection.

\paragraph{What the models received.}
Full sends the checkpoint as formatted text: the brief, delivery requirement, file identity, applicable inspection measurements, observation and decision question. Summary asks the executor to describe decisive evidence in its own words. The host appends the common decision question and checks the total text length. Scoped uses the production handoff builder to serialize the quoted brief, revision, observations, file and log digests, checks and question. Summary and Scoped each have a 4,000-character ceiling. The cap applies to the outgoing text. The same source PNG or PCM WAV bytes were attached separately to the advisor request in every applicable arm.

For example, in archived task \texttt{text-009} the public assertion admitted strings whose length equaled the threshold. Full included that assertion in the inspection record. Summary interpreted it as an inclusive threshold and suggested an implementation. Scoped quoted the inspection and bound it to the revision and log digest. These are different transformations of the same checkpoint: one can introduce an interpretation, while another can repeat literal evidence alongside additional identifiers. Ground-truth hidden assertions did not travel in any packet.

The executor was requested under the recorded identifier \texttt{gpt-6-luna} at maximum reasoning effort. Text and charts used the Codex subscription route for \texttt{gpt-6.2-astra} at medium effort. Audio used the configured \texttt{gemini-subscription-argon} gateway route. The advisor received a common four-field reply instruction within a modality. A valid action or request for evidence could be passed back. If a reply failed parsing or the route was unavailable, the executor could still submit. The final executor received its textual checkpoint and usable advice. It had no direct media attachment in the submission step. For chart and speech tasks, the advisor was therefore the model with direct access to the original pixels or samples.

\paragraph{Endpoint and costs.}
A grader with no arm input scored each submitted file. MBPP submissions ran against the original assertions in a fresh network-isolated Python container. Chart answers passed on a case-insensitive reference match or a finite numerical value within 5\% relative error; a zero reference required numerical equality. For speech, we case-folded the text, replaced punctuation with spaces, normalized whitespace, and accepted a word edit distance at most 15\% of the reference word count. An assignment counted as verified only if grading succeeded within \Deadline{} seconds of starting that assignment. Preparation, consultations, submission and grading were inside this deadline.

For the primary contrast let $W$ count tasks verified only under Scoped in the Full--Scoped pair, and $L$ count those verified only under Full. The observed rate difference is $(W-L)/n$. We inverted the paired score test using the constrained multinomial model of Tango \cite{tango}. Noninferiority required a one-sided 95\% lower bound strictly above $-5$ percentage points on the equal-strata workload. The margin is a design tolerance. Other contrasts and stratum-specific bounds are descriptive.

We estimated API-equivalent dollars from the frozen rate card and the executor and advisor receipts, including the summary-generation request and failed attempts when usage was available. For an arm, cost per success is the total estimated request cost divided by the number of verified deliveries in the \emph{same} priceable task set. The prespecified cost criterion required a one-sided 95\% upper bound of at most 0.90 on the Scoped/Full ratio. The analysis resampled complete task pairs within modality 10,000 times. An unpriced route leaves the corresponding full-workload estimand unidentified. Elapsed time includes local and service delays. The estimates describe request-equivalent prices rather than charges on a subscription bill.

\section{Discussion}
A handoff has at least two jobs: carry observations forward and make it possible to check which file those observations describe. On a short programming checkpoint, adding an artifact digest and a separately named log digest can increase the text budget even when both identifiers serve a valid purpose. An interface that promises compression should measure the transmitted packet against the actual baseline for that task. A character ceiling describes a maximum, while the paired measurements describe what the system sent.

The structured workflow met the registered quality tolerance on the target mixture. The comparison offers little reason to prefer its aggregate success rate over a free summary here. Choosing between the two also requires knowing where computation occurs, whether a user needs traceable evidence, and which failures matter. In particular, an application using the executor for its own media inspection would have a recovery path the present executor lacked.

\paragraph{Limits to inference.}
The three benchmarks contain short public tasks that may have appeared in training. Sampling removed duplicate source items, but repeated speakers, task templates and shared chart conventions can induce residual dependence. A code module passing the supplied assertions may still fail another specification-consistent input. The speech threshold can accept small transcription errors. Thresholds, equal modality weights and the deadline characterize this workload; changing them defines a different estimand. One realization per task and arm samples hosted-model and service variability without separately estimating it. The paired bound uses a pooled matched-task model and does not estimate variation across provider revisions or deployments.

Advisor identity varies with modality. Cross-modality differences can reflect the input, the route, or its response parser. The study uses a constructed inspection checkpoint and mandatory consultation. It supplies no comparison with local-only execution, spontaneous escalation, real longitudinal repository work, or a developer choosing what to send. The separate native-host walkthroughs used automated testers and do not measure human adoption. Local hardware and subscription charges also limit the financial interpretation. A follow-up could sample longer naturally occurring checkpoints and cross media access at submission with handoff format, measuring both packet length and final verification under a complete rate card.
