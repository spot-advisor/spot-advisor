# Spot Advisor 2.4：公开稳定版与论文证据冻结

**2.4 完成时，普通用户能在 Codex 或 Claude Code 中安装并用文本、图片和音频完成一次真实交付；论文作者能从同一个发布版本重建主表、图和统计区间。** 此后冻结产品行为和主实验数据，把重心转向写作、审阅与 arXiv 投稿。

三个研究方向里，主线选定为 **“一次顾问调用中，压缩交接能否保住交付质量，并降低成本？”** “何时值得问”留作后续研究；“跨宿主真实使用”纳入公开发布验收。这样既覆盖公众使用，也能把最多 200 个独立任务的预算集中在一个可回答的问题上。

## 一、公开版要补齐的四件事

| 工作 | 2.4 的完成条件 |
|---|---|
| **首次安装与升级** | 新用户按公开 README 安装后，能用 `--doctor` 查看实际调用的脚本、版本、可用后端和支持的输入类型。用干净安装和残留 2.2 副本的环境各验一次，验证升级与回退。 |
| **三种输入都能交付** | Codex、Claude Code 各跑通文本、图片、音频，共六条用户路径。文本用实际修复和测试验收；图片任务必须读取截图才能答对；音频任务必须辨认原始 WAV 中的片段并给出可核对的时间点。公开支持表列明每条路径所需的后端和凭据。 |
| **用户知道发了什么，失败后能继续** | 发出前可预览问题、验收条件、引用证据和附件清单。交付评审保留决定合格与否的条件，并区分产物版本与检查日志的哈希。覆盖中文问号、用户更正、旧回复、超时和后端不支持媒体。失败时说明缺什么；可能已发出的请求不会被自动重复发送。 |
| **有人能独立用起来** | 至少两位未参与开发的使用者分别从公开说明开始，覆盖两个宿主和三种输入，完成“安装 → 预览 → 咨询 → 应用 → 验证”。记录他们需要作者帮助的步骤，修正说明后由新会话重走。 |

发布验收首先重放已发现的缺陷：错误 CSV 和错误邀请页都必须被拦下；条件齐全、内容正确的对应文件也必须能通过。两端同时测试，可以发现“一律要求补证据”造成的假改善。[既有实验证据](spot-advisor-2.4-findings.md)

## 二、论文主实验只改变交给顾问的上下文

从**同一个已保存的任务决策点**分出三组。每组使用相同的执行器、顾问、问题、原始附件、一次咨询机会和剩余执行时间。顾问返回后，执行器继续处理任务，由独立验证器检查最终产物。

| 实验组 | 顾问收到的内容 | 回答的问题 |
|---|---|---|
| A · 完整记录 | 截至决策点可共享的完整任务记录及原始附件 | 给足可用上下文时，交付质量和成本是多少？ |
| B · 普通摘要 | 同一执行器撰写的自由文本摘要，使用和 C 相同的文字上限及原始附件 | 同样短的情况下，结构化交接有什么额外价值？ |
| C · Spot Advisor 2.4 | 当前要求、产物版本、对应证据、待决问题及原始附件 | 2.4 能否在压缩上下文后保住质量，并节省整体成本？ |

- **样本。** 文本、图片、音频等额分层。先用 18 个独立任务做先导，每种 6 个，估计配对结果分歧率。按 80% 统计功效计算正式样本量，在查看正式结果前锁定。正式任务最多 180 个，含先导最多 198 个；每个任务跑三组。重复运行、翻译和同一素材的改写都不重复计为独立任务。
- **质量。** 主指标是截止时间内独立验收通过的任务比例。主比较为 C 对 A，两组通过率差的一侧 95% 置信下界必须高于 **−5 个百分点**，才支持“保住交付质量”。分别报告三种模态的结果和区间。样本上限造成的精度不足如实写进论文。
- **成本。** 统计准备摘要、构造交接包、顾问调用、后续执行和失败尝试的完整开销。报告每次验证成功交付的成本、执行器与顾问 token、媒体计费和耗时。沿用项目的节省门槛：成本比置信上界达到 **0.90 或更低**才宣称至少节省 10%。订阅路线的估算金额标为 API 等价成本，缺失用量单列。
- **防止高估。** 正式题目、判分标准、提示词、模型配置和分析代码提前冻结。三组看见相同字节的图片或音频，完整记录组不接触隐藏答案。客观任务由测试、解析器或最终文件判定；感知任务由不知道组别的评审按预定标准判定。原有 156 次诊断用作开发回归，正式结果来自新任务。

## 三、冻结顺序与发布决定

1. **先冻结候选产品。** 完成交付条件覆盖、版本诊断、双语提问及三模态支持。通过六条真实路径、回归测试和新用户验收后，锁定候选提交，再启动正式实验。
2. **再冻结论文证据。** 保存预注册方案、任务与素材授权、分组清单、去标识记录、失败记录、产物哈希、判分器及生成图表的命令。由另一环境从干净检出重建主表和全部图，并抽样重判三种模态的原始产物。
3. **最后发布同一版本。** 官方仓库与 `stancsz` 镜像的 `main`、`v2.4.0` 标签指向同一提交。中英文 README、支持矩阵、升级说明、引用信息和论文稿架都引用这份证据。稿架应能用随附的 TeX、参考文献和图片独立编译，旧研究 PDF 与 2.4 结果清楚区分。[现有论文材料](../paper/README.md) · [arXiv 官方 TeX 指南](https://info.arxiv.org/help/submit_tex.html)

**发布与研究各有验收标准。** 三模态公开路径中的阻断性缺陷会推迟稳定版；质量或成本假设没有得到支持，也可以形成完整的论文结果。证据可复现、产品通过验收后即可结束 2.4，后续集中写论文。

## 执行记录与论文定稿计划

项目负责人随后批准由 Spot Advisor 自动测试者分别操作两个原生宿主。产品与实验已冻结在 [2.4 正式版](https://github.com/spot-advisor/spot-advisor/releases/tag/v2.4.0)，[验收记录](release-2.4.md)与[复现记录](../eval/results/spot24-release/reproduction.json)保留实际覆盖范围。

1. 在冻结的数据上独立核对三组逐题配对、各模态区间、使用量、缺失计价与可计价任务的单位成功成本。保留完整记录、自由摘要、结构化交接的原定义，写明原始媒体对谁可见。
2. 完成英文论文的摘要、引言、相关工作、方法、结果、讨论、局限与复现说明。将预注册的主比较与描述性比较分开，所有实验数字从已发布记录生成。核对方法与引用的原始来源。
3. 从干净检出重建表图、编译 TeX 源码包，检查每页排版、交叉引用与稿件元数据。发布可直接阅读的 PDF 和独立编译的源码包，同时保留稳定软件标签与原始证据稿。投稿所需的标题、摘要、作者及分类另附于论文目录。

论文版本使用单独的研究分支与版本标签，两个软件仓库的 main 继续指向已验收的 v2.4.0。完成条件是可公开引用、可复现、可供作者向 arXiv 提交的稿件。公开投稿涉及作者同意与许可选择。
