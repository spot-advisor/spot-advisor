# Spot Advisor 2.4 diagnostic protocol

Baseline: published 2.3 at `14eacdc`. These author-designed, synthetic diagnostics identify failure mechanisms and prioritize changes. They do not establish release efficacy. Freeze the cases, factors and rubric in the run manifest before responses arrive.

1. Run the repository suite and compare the discovered local skill texts and actual CLI options with the published copy. Use local previews for format, evidence registration and request budget boundaries.
2. Exercise six first-decision checkpoints in English and Chinese, in fresh Luna Max sessions. Cross the existing rule versus one extra pending-check instruction with ordinary versus actionable local rejection feedback. Feedback is present only in the two rejection scenarios; identically worded cells elsewhere measure ordinary sampling variation. Shuffle the four arms within each case/language/repeat block and shuffle blocks with seed 2401. Two repeats, 96 assigned single responses. The first endpoint is the correct next tool. For expected consultations also score compatibility with the published scoped question validator. Report by scenario, language, treatment and repeat. With only six semantic scenarios, counts are descriptive.
3. Submit real delivery reviews to the published scoped CLI using Astra. Cross valid versus defective output with the specific requirement quoted versus present only in the local task state and on the unquoted line of the original brief. Two artifact families and two fresh repeats make 16 assignments. Keep all checks, observed values and host requirements constant across quote conditions within each artifact. Randomize with seed 2402. Count ACCEPT on defective artifacts, ACCEPT on valid artifacts, REWORK, NEEDS_EVIDENCE and all unusable responses. Check the local preview of exactly what the reviewer received. The gold comes from inspecting the bytes of the artifact.
4. Recount the previous replication from the public assignment records. Keep local attempts, dispatches, executor usage, Frontier usage and verified deliveries separate. An infrastructure failure remains in the denominator of its assigned cohort.

Use subscription routes with no paid API fallback, at most four concurrent executor requests or two reviewer requests, one response per assignment, 60 seconds per executor request and 90 seconds per review subprocess. One unscored live smoke per route must succeed before its cohort. Keep IDs opaque to models, save the raw receipts locally and export sanitized outcomes, hashes, model, elapsed time and usage. Do not retune during the runs or pool repeats as independent tasks. A ranking in this screen only warrants confirmation on unseen work.
